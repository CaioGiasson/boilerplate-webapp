## Decisões tomadas

D1 (`User.role` separado), D2 (`AiLog` fora da TX), D3 (modelo de texto por env, default `gpt-5.4-mini`) e D4 (sem rota HTTP de IA) seguem o combinado. D7, D8, D9 e D11 foram resolvidas **na implementação** como indicado acima; D5, D10 e D14 também. **D6 (scripts de push), D12 (retenção de `AiLog`: 90 dias) e D15 (política de senha duplicada, coberta por teste de paridade)** foram decididas aqui e podem ser revistas.

## Não foi verificado

- **CI em Linux:** não rodei o workflow do GitHub localmente. A PR roda o `CI / verify`; a checagem do lockfile e o `npm test` cobrem o risco conhecido (binários nativos).
- **Fluxos com MongoDB/Docker real:** `docker compose up`, `prisma:push`, `healthcheck` contra banco e `smoke:multi-instance` **não foram executados**. Os repositories são testados com Prisma simulado; as rotas foram exercitadas num servidor de produção local **sem banco** (cabeçalhos, 401, boot com VAPID parcial).
- **Entrega real de push** a um navegador, instalação do PWA e comportamento do service worker em Chrome/Safari: os handlers são testados por execução do `sw.js` em sandbox, mas **não** num navegador real.
- **Migração de dados existentes:** `npm run user-role:backfill` e `npm run files:backfill-thumbnails` têm `--dry-run`, mas **não foram rodados** contra dados reais.
- **Jurídico:** a política de privacidade em `content/legal` **não foi alterada**. Admin acessar contas (ADR-013), prompts em `AiLog` e envio a OpenAI/serviços de push (ADR-012, ADR-015) precisam de revisão jurídica e de preencher os DPAs em `docs/operators/subprocessors-ropa.md`.
